# Bugzap v1 build plan

## Context

Bugzap is a pin-drop feedback tool: a reporter clicks anything on a page, a pin drops there, and a report goes out with the URL, the element, the click point, the viewport, a screenshot, and diagnostics. It replaces the idea of building this inside Routeloop, so that Routeloop and every other Feral Creative project can use it, and it is meant to become a freemium SaaS under FSL-1.1-ALv2. The repo is currently docs plus `reference/routeloop/`, a read-only copy of Routeloop's production feedback system to port from.

Decisions made 2026-10-18: v1 ships the widget and the hosted backend together; the backend runs on Cloudflare Workers (D1, R2, Static Assets, Email Service); screenshots are automatic DOM capture (modern-screenshot) with an upload fallback; reporters are host-identified only, through a signed token; Routeloop moves to the hosted backend; kinds are bug, idea, and question; dev ports are Worker 2833 and demo host site 2834. Billing is out of v1, but the schema is multi-tenant (accounts, sites, reports).

## Shape

It is one npm package, not workspaces, with a separate tsconfig per area because DOM and Workers types conflict. The dashboard is server-rendered Hono JSX in the same Worker, the Routeloop pattern: one deploy, a same-origin session cookie, and no CORS.

```text
src/core/     pure TS, Web Crypto only: ids, image-policy, image-strip, diagnostics, policy, identity, url, anchor, payload, limits
src/widget/   framework-free embed: index, guard, buffer, diagnostics, api, upload, anchor/{capture,resolve}, ui/*, capture/screenshot (lazy chunk)
src/worker/   Hono app: ingest/, pins/, auth/, dashboard/, emails/, db/ (scoped.ts), mail, notify, crypto
migrations/0001_init.sql
demo/         index, builder (innerHTML rebuild), map (cross-origin iframe), spa, served on :2834
utils/        open-when-ready.js, demo-server.js, build-widget.js, seed-site.js, sign-identity.js, mint-login-link.js
test/core  test/widget (happy-dom)  test/worker (@cloudflare/vitest-pool-workers)
docs/         ROADMAP, architecture, embed, identity, decisions
```

`npm start` runs `utils/open-when-ready.js` (ported from `~/www/ezzat/money.ezzat.com/utils/open-when-ready.js`), `utils/demo-server.js` on 2834, and `wrangler dev --port 2833`, whose `build.command` rebuilds the widget on save. `OPEN_BROWSER=0` and `start:no-open` skip the browser.

## Key design

The data lives in D1, with these tables: `accounts` (plan defaults to `free`), `users`, `memberships`, `login_tokens`, `sessions`, `sites` (public key `bz_pk_…`, secret encrypted with AES-GCM under the `SITE_KEK` Worker secret, plus the previous secret for 24h rotation grace), `site_origins`, `reporters`, `reports` (Routeloop's state/status split), `pins` (anchor JSON), `attachments` (R2 keys, generated by the server only), and `diagnostics`. Ingest writes in one atomic `db.batch()` and uses subselects instead of `last_insert_rowid()`.

The embed is a queue stub plus an async script tag, `Bugzap('init', { site, identity })`, with `identify`, `logout`, `open`, `close`, `context`, and `on` commands. It renders in a shadow root and uses the top-layer popover where the browser supports it. Every entry point is wrapped in `guard()` and nothing rethrows into the host page. It never uses `innerHTML`. Host pages can mark elements with `data-bugzap-id` (stable anchor), `data-bugzap-mask` (blanked in screenshots), and `data-bugzap-ignore` (cannot be pinned). The target is under 15 KB gzipped, with the screenshot code in a separate chunk loaded on first use.

The identity token is an HS256 JWT signed by the host over `sub`, `email`, `name`, `iat`, and `exp`. Signing all of them, not just the id, stops a reporter from swapping in someone else's email. The server rejects any other algorithm, verifies in constant time, caps tokens at 7 days, and recommends 24h to hosts. Sites without their own login can't use v1; the future fix is reviewer invites over magic links, which is not built now.

A pin's anchor is built from the stable attributes on the element and its ancestors (`data-bugzap-id`, `data-testid`, and so on, or an `id` that doesn't look generated), plus a scoped selector, the tag, the text, the label, the element's rect, and the click offset as a fraction of the box. Re-anchoring tries the exact attribute first, then the ancestor plus a relative selector, then the full selector, then a fuzzy score over candidate elements. If all of those fail, the pin goes at the original point scaled to the viewport and is drawn dashed as approximate. A MutationObserver re-resolves pins after `innerHTML` rebuilds.

Ingest is `POST /v1/reports` as multipart, with checks ordered cheapest first: size cap, site key, origin allowlist, identity token, burst limits through the Workers rate-limit binding, the hourly limit counted in D1 (10/hour), payload parse, image sniff (PNG or JPEG only, max 2 MB) plus metadata strip, diagnostics redaction, R2 write, and the D1 batch. The owner email goes out through `waitUntil` after commit and never throws.

A screenshot is a viewport render cropped to about 1200×800 around the pin, JPEG at quality 0.85, with a 5 s timeout. If the area under the pin comes out blank, as with WebGL maps or iframes, the widget prompts for an upload instead. Images are served only through a session-gated proxy with `nosniff` and a sandbox CSP, and the R2 bucket is never public.

The dashboard signs owners in with a magic link: a GET shows a confirm page and a POST consumes the token, so email link scanners can't burn it. Sign-in is limited to `SIGNUP_ALLOWLIST`, with mail printed to the console in dev. The dashboard covers sites (show the secret once, rotate it, edit origins), a per-site reports inbox, and report detail with state, status, priority, a note, and "Open on page" through a 15-minute view token. Every query goes through `db/scoped.ts`, so another account's report returns 404.

## Ported from reference/

Each reference file is deleted in the same PR that ports it. `slug.ts` goes to `core/ids.ts`. `images/policy.ts` goes to `core/image-policy.ts`, and a new `image-strip.ts` replaces sharp, which can't run in Workers. `feedback/diagnostics.ts` and `parseDiagnostics` go to `core/diagnostics.ts`. `feedback/policy.ts` goes to `core/policy.ts`, keeping the limits, `titleFrom`, `visibleTo`, `STATUS_META`, and its label test. `feedback-buffer.js` goes to `widget/buffer.ts`. `collect()` and `shrink()` from `feedback.js` go to `widget/diagnostics.ts` and `widget/upload.ts`. The email shell and the owner template go to `worker/emails/`. The `notify.ts` and `mailer.ts` patterns go to `worker/notify.ts` and `worker/mail.ts`. `rider-feedback.md` is distilled into `docs/decisions.md`. `faq.ts`, `storage.ts`, and `process.ts` are not ported.

## Open questions, deferred

The domain (.app or .io), screenshot retention (proposed: R2 lifecycle at 180 days), keeping query strings (proposed: stripped by default, with a per-site allowlist), and the main risk, which is modern-screenshot's speed on Routeloop's builder DOM. That is proved or disproved in milestone 6.
